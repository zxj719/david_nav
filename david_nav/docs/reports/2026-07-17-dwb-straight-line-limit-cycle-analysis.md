## 0. TL;DR

**正弦轨迹不是底盘"走不直"，是外环（DWB）在打一个稳定的极限环（limit cycle）。**

- 串口指令数据显示：wz 指令以 **6.6–9.4 s 周期近乎对称地左右交替**（自相关最高 +0.72），
  单 goal 净角度积分只占总纠偏活动量的 **1–10%**，且正负号在 goal 之间来回变。
  → **恒定性双轮不平衡不是主因**（若是，纠偏应长期单边）。
- 同一晚同一硬件，03:23 场次 goal#4 全程 67 s **wz RMS 仅 0.10、零饱和、零停车**，
  而前后其它 goal RMS 0.28–0.40、10–45% 时间 wz 打满 ±0.5。
  → 硬件当晚没变，变的是环路的激励状态。**过热/效率退化假设与数据不符**
  （24 分钟连续运行的场次里，最后两个 goal 反而是最干净的）。
- 振幅"越走越大"是真的（03:48 goal#1 的 RMS 17 s 内从 0.13 涨到 0.41；
  goal#4 后半程持续 0.40–0.46 直到人工取消），但它每个新 goal 会**秒级重置回小值**。
  电机热时间常数是分钟级，5 秒重置不可能是热效应——这是**控制暂态**的指纹。
- 根因是三个叠加的 **模型-执行失配**，把一个欠阻尼环推成极限环（详见 §4）：
  1. 底盘 wz 执行增益未标定（原地实测 ~2.5×，滚动态未测且强非线性/静摩擦主导）；
  2. `david_move` 把 (0, 0.15) 的 vx 全部抬到 0.15 —— DWB 的 5 档速度采样有 4 档
     在执行端是同一个动作，规划曲率与执行曲率最大差 4×；
  3. BT 以 1 Hz 从机器人当前位姿重规划全局路径 —— 横向参考线每秒重新锚定到
     机器人自己身上，环路没有"原直线记忆"，振荡中心随机漂移，视觉上=振幅增大。

另发现工具链 bug：**当晚所有 rosbag 全部录制失败**（脚本先建目录，
`ros2 bag record --output` 拒绝已存在目录），本分析只能基于 wheeltec 串口日志。

## 2. 当晚实际生效的控制结构（与 CLAUDE.md 描述已不同）

```
DWB(20Hz, 连续采样 vx×5 / wz×20) → /cmd_vel_nav
  → velocity_smoother (10Hz, CLOSED_LOOP, 基本透传/偶见斜率限幅)
  → david_move (50Hz)                ← vx∈(0,0.15) 一律抬到 0.15；max 0.20
  → wheeltec → STM32 (P 轮速环)
```

- **cmd_vel_separator 已不在链路中**（binary/互斥/brake 全部退出）。
- 关键参数（install 为 symlink，yaml mtime 2026-07-16 11:43 < run 时间，确认生效）：
  `max_vel_x = max_speed_xy = 0.15`，`min_vel_x = 0.0`，`max_vel_theta = 0.5`，
  `vx_samples 5 / vtheta_samples 20`，`sim_time 1.5`，`controller_frequency 20`，
  critics：PathDist **30** / PathAlign 12(fpd 0.3) / GoalDist 10 / GoalAlign 6 /
  Oscillation / BaseObstacle（RotateToGoal 已移除）。
- BT `navigate_to_pose_w_david_embedded_recovery.xml`：`RateController hz="1.0"`
  → **每秒从当前位姿重规划全局路径**。
- 串口观测到的 wz 值精确落在 DWB 的 20 点采样格 (−0.5 + n·0.0526) 上
  → 串口≈DWB 原始输出；vx 则被 david_move 钉死在 {0, 0.150}（recovery 时 0.2）。

### 3.3 从指令反推的底盘固有偏差上界

0348-g4：净角度积分 −1.42 rad / 滚动 ~110 s ≈ 指令侧 −0.013 rad/s。
即使按原地实测增益 2.5× 折算，底盘固有偏航偏差 ~**0.03 rad/s 量级**
（0.15 m/s 下等效直行半径 ≥ ~5 m）。而环路为了"修"它，打出的是 ±0.5 指令
（折算实际可达 ~±1.25 rad/s）——**纠偏幅度比缺陷本身大一个数量级以上**。
且该偏差的符号在 goal 间不固定（+,−,+,−…），更像路径曲率/地面/航向相关，
而非固定的左右电机差。

### 3.4 尾声事件链（0348 g4 之后）

振幅增大 → 摆进膨胀区 → `RobotEmbeddedInObstacle confirmed (3/3)` ×4 →
BT recovery：backup → `Pose Goes Off Grid` + `Collision Ahead - Exiting DriveOnHeading`
→ backup failed。即"越走越大直到导航失败"在日志里有完整闭环。
另有 CPU 压力证据：planner "missed its desired rate 20 Hz → 6.1/15.5 Hz"、
controller 偶发 missed 20 Hz。

## 4. 机理（电控视角）

把直线跟踪画成环路：

```
横向偏差 e, 航向差 θ ──► DWB critics(PathDist 30/PathAlign 12) ──► (vx*,wz*)
      ▲                    │ 内含 1.5s 前向仿真，假设执行增益 = 1
      │                    ▼
  lightning 位姿      david_move: vx∈(0,0.15)→0.15（4/5 采样档同一动作）
  (TF 容忍 1s)             ▼
      │              STM32 P 轮速环 + 70 kg 惯量 + 静摩擦
      └──────────── 实际 wz 增益 g(ω)：原地实测 ~2.5×，滚动态未标定、强非线性
```

1. **前向模型失配 = 环路增益错误。** DWB 不是 PID，但它的每一步选择都建立在
   "我发 (vx,wz)，1.5 s 后机器人在哪"的仿真上。yaml 注释自证 v 通道增益 ~1.2×
   （"0.20 实跑 ~0.24"），角通道原地实测 ~2.5×（2026-07 位置环复盘）。曲率
   κ=ω/v 的执行/规划比 ≈ 2×。对一个按单位增益调出来的打分权重组
   （PathDist 30 是 bench 上调的），等效开环增益直接翻倍——欠阻尼直至负阻尼。

2. **静摩擦 + 死区补偿架构把执行集合离散化。** 用户的"地面静摩擦大"判断在
   机理上成立，但作用路径不是"拉弯直线"，而是：为踢穿静摩擦装的
   `min_linear_x=0.15` 地板恰好等于 DWB 的 `max_vel_x`，vx 通道从连续变量
   退化成 {0, 0.15} 两点集。DWB 想用"减速+小曲率"温和纠偏时，执行端仍是
   全速——纠偏弧比规划浅得多 → 偏差继续长 → DWB 加大 wz → 直到打满或干脆
   vx=0 原地回转（波形里的大写字母、123 s 内 40 次停走）。这就是张弛振荡
   （relaxation oscillation）的产生器。滚动态下小 wz 需要内侧轮减速穿过
   摩擦死区，同样贡献"先没反应、后过量"的继电器特性。

3. **1 Hz 重规划抹掉了直线记忆。** GridBased 每秒从当前位姿重新拉一条到
   goal 的线，PathDist/PathAlign 随即以新线为准——横向误差每秒被"赦免"。
   环路对**原来那条直线**的回复刚度≈0，只剩对 goal 方位的追踪。于是振荡
   中心做随机游走，叠加在 6.6–9.4 s 周期的航向振荡上，宏观表现正是
   "正弦且幅度越来越大"。λ = v·T ≈ 0.15 × (6.6–9.4) ≈ **1.0–1.4 m 波长**，
   与现场观感吻合。

4. **相位预算本来就紧。** 20 Hz 控制 + 10 Hz smoother + 50 Hz 桥 + 串口 +
   P 轮速环 + 70 kg 偏航惯量；`transform_tolerance: 1.0` 允许用到 1 s 旧的
   位姿——在 T≈8 s 的振荡频率上 1 s 相当于 45° 相位损失。CPU 过载告警
   （planner 掉到 6 Hz）说明位姿/路径新鲜度在实跑中确实会劣化。

5. **饱和 ±0.5 决定了极限环的"等幅"段**（描述函数意义下），0323-g2 的
   90 s 等幅波形是标准形态；0348 场次的"增长"段是从小初值向该环收敛 +
   横向漂移叠加的过程。

### 对用户三个假设的裁定

| 假设 | 数据裁定 |
|---|---|
| 双轮驱动不平衡，同指令不同速 | **存在但被高估**：指令净偏置仅 1–10% 且符号不定，折算固有偏差 ~0.03 rad/s（直行半径 ≥5 m 级）。它是振荡的**种子**之一，不是放大器。P 环无 I 项确实会留负载相关稳态差——用 §6 的分轮遥测量化它，别猜。 |
| 过热/超时限运行 → 效率下降 → 幅度变大 | **当晚数据不支持**：幅度在新 goal 开始后秒级重置；24 min 连续运行的场次里最后两个 goal 最干净；无单边化趋势、无热折返特征。热问题值得装遥测长期看，但它解释不了本现象。 |
| 静摩擦太大只能靠不断纠偏 | **机理成立、路径不同**：静摩擦通过"死区补偿地板=DWB 上限"这个架构巧合毁掉了速度通道，并给 wz 通道装了继电器特性。修的是标定与架构，不是地面。 |

## 5. 修复路线（按杠杆率排序）

1. **【根修】标定底盘执行增益（v、ω 两通道，滚动态）。**
   controller_bench + slam_gt 真值已具备。方案：直线 vx∈{0.15,0.20} 阶跃、
   滚动中 wz∈{±0.1,±0.25,±0.5} 叠加阶跃，各 ≥5 组，量增益+纯滞后+死区；
   修正系数落在 wheeltec 固件（首选，运动学参数 track/wheel-R 很可能在
   2026-06 换宽轮距/大轮后没同步）或 twist_transform。验收 |g−1|<10%。
   **在此之前调任何 DWB 权重都是在错误的植物模型上白调。**
2. **【解量化】让"DWB 认为的速度 = 执行速度"。**
   二选一：`min_vel_x: 0.0 → 0.15`（模型与地板一致，DWB 只在 {0.15} + 原地转
   之间决策，诚实的两点集）；或实测新电机最小可滚动速度后把
   `david_move.min_linear_x` 降下来，还 DWB 一个真连续通道。
3. **【线记忆】重规划降频/换锚。** BT `RateController 1.0 Hz` →
   `DistanceController`（如每 1–2 m）或 SpeedController；让 PathDist 有一条
   稳定的线可贴。若继续深投 DWB 不划算，差速直线工况上 Regulated Pure
   Pursuit 是结构性更合适的控制器（曲率=显式反馈，无采样-打分抖动）——
   但**必须在 #1 完成后再评估**，否则一样振。
4. **【立竿见影的止血】压极限环幅值**（不治本，现场可先用）：
   `max_vel_theta 0.5 → 0.30`、`decel/acc_lim_theta` 收紧、
   `transform_tolerance 1.0 → 0.3` 并盯 CPU（planner 6 Hz 告警要消）。
   #1 完成前不建议再动 sim_time/critic 权重。
5. **【电气中期】** STM32 轮速环加 I 项/速度前馈（消负载相关稳态差——这才
   是对"双轮不平衡"假设的正解）；上报分轮速度/电流/温度进 ROS
   （`/joint_states` 或自定义 topic）——一次到位终结"猜轮子"的循环。
6. **【工具链】** 修 bag 输出路径 bug（§1）；bench 直线验收判据建议:
   10 m 直线，串口 wz RMS < 0.08 rad/s、饱和占比 0%、真值横向峰值 < 0.10 m、
   vx 停走切换 0 次。
