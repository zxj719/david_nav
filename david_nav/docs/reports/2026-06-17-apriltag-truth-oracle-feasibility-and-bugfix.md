# AprilTag 车载真值方案：可行性评估 + 脚本 bug 修复

- 日期：2026-06-17
- 范围：评估 `apriltag.rar` 交付的车载相机 AprilTag 实时位姿方案，能否做 David 导航的近似真值监测；修复其中导致默认跑错的 bug。
- 关联：[P0 真值管路 spec](../../../2026-06-15-truth-oracle-p0-spec.md)、[P1 自动调优 spec](../../../2026-06-15-autotune-p1-spec.md)
- 代码落点：`src/apriltag/`（由 `apriltag.rar` 解压整理而来）

## 1. 一句话结论

**可行，但交付的脚本只做了一半，且有一个让它默认跑错的 bug。** 它能算"标签在相机系下的位姿"，但没算"机器人在场地系下的位姿"——后者才是要的真值。bug 已修。补齐自标定 + 解算链后，能拿到 **厘米级位置 / 1~2° 偏航** 的近似真值，足够用来校核 nav2/lightning 定位漂移、驱动 A→B 导航调参；但达不到动捕级绝对精度。

## 2. 交付物分析（`apriltag_pose.py`）

| 项 | 内容 |
|---|---|
| 相机 | **鱼眼** RGB，1920×1080，USB |
| 内参 | fx≈675, fy≈671, cx≈959, cy≈531；鱼眼畸变 D=[0.46, -0.22, 0.45, -0.19]；标定 rms=0.50px（质量好）|
| FOV | 水平 ≈ 160°+（强鱼眼）|
| 流程 | 鱼眼去畸变 → `cv2.aruco` 检测 tag36h11 → `solvePnP(IPPE_SQUARE)` → 输出每个 tag 的 rvec/tvec（**相机系**）|
| 标签 | 提供 id00~id09 共 10 张 tag36h11，**8×8 黑边布局**（6 数据 + 每边 1 黑边框）|

**输出止于"相机 ↔ 标签"。** 没有 tag→场地地图、没有相机外参、没有变换链，所以拿不到机器人真值。完整真值链需要：

```
T_world_base = T_world_tag · inv(T_cam_tag) · inv(T_base_cam)
                ↑要标定/自标定  ↑脚本已给     ↑要标定
```

## 3. 发现并修复的问题

### 3.1 核心 bug：鱼眼去畸变代码是死的（已修）

原 argparse：

```python
ap.add_argument("--no-undistort", action="store_true", default=True, ...)
```

`store_true` + `default=True` → 这个开关**永远是 True**，命令行无法关闭。结果整个 docstring 吹的"去畸变保证精度"路径**从未执行**：强鱼眼原图直接喂进针孔模型的 `solvePnP`，位姿系统性偏移，**图像边缘最严重**（而标签常出现在边缘）。

**修法**：改成正常的 opt-out 开关（默认 False → 去畸变默认执行）。要关才显式加 `--no-undistort`。

### 3.2 tag-size 默认值（已设）

`--tag-size` 要的是**黑边外沿边长**，不是单格。通过解析生成的 PNG 确认 tag36h11 = **8 模块**宽。用户实测每格 35 mm：

```
tag-size = 8 × 0.035 = 0.28 m
```

默认值设为 0.28，注释写明来由，仍可 `--tag-size` 覆盖。原来该参数 `required=True`，现去掉。

### 3.3 实时模式分辨率陷阱（已修）

内参在 1920×1080 标定，但 `VideoCapture` 默认常给 640×480。原 live 模式会拿 1920 的内参处理 640 的帧 → 位姿全错且无提示。**修法**：live 模式显式请求标定分辨率，不匹配则打印告警。

修改后已验证：`no_undistort` 默认 `False`、`tag_size` 默认 `0.28`、语法通过。

运行：`python apriltag_pose.py --live --camera <idx> --show`

## 4. 精度预期（量级估算）

- fx≈675、tag 0.28m：1m 处 tag 约占 190px，平移误差 mm~cm 量级。
- **旋转是误差大头**：平面单 tag 的离面旋转噪声大 + 存在位姿翻转（flip）二义性，单 tag 远距可能跳变 → 必须**多 tag 联合解算**消歧义（与 P0 spec §1 一致）。
- 误差随距离增长、随可见 tag 数减少而恶化。
- **最大误差源**：标签在场地系的位置精度（人工摆放/自标定的精度直接进真值）。

---

## 5. 对"开机转一圈自标定"路线的评估（用户简化方案）

用户决定**不做精确 tag 测绘**，改为每轮开始原地转一圈、算出标签相对位置即可。评估：**对 A→B 调参目标成立**，边界如下：

- 转圈自标定出的 tag 相对位置，精度 = **转圈时轮速计精度**。David 这套差速 + 脚轮底盘轮速计本就脏（脚轮打滑、轮速 3× 存疑）→ 出来的不是绝对真值。
- **但对调参够用**：标签固定不动，每轮重新观测同一批 tag，apriltag 把轮速计累积漂移按死（全局锚定）。A→B 调流畅/稳/准要的是**跨轮相对一致参考**，不是绝对地理坐标。
- 这正是 P0 spec 的简化版：把"全站仪/BA 测绘 tag 地图"换成"开机转圈拿相对 map"——省事，代价是绝对精度，符合 P1"管路验证非收敛"的定位。
- 后续可把轮速计 + apriltag 融合成**近似真值 odom**（apriltag 治漂移、轮速计补 tag 丢失/高频），即 P1 `trial_runner` 订阅的 `/groundtruth/pose`。
