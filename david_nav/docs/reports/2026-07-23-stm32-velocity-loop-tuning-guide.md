# STM32 底盘速度环调参指导（基于 2026-07-23 闭环实测基线）

面向：固件同学。目标：**不动增益、只提带宽** —— 把 cmd→整车响应纯滞后从
0.6–0.9s 压到 ≤0.2s。增益这次已经调对了，别再动它。

## 1. 现状基线（2026-07-23 headless run，bag 闭环实测，r=0.86–0.97）

| 量 | 实测值 | 判定 |
|---|---|---|
| wz 执行增益（实际/指令，滚动态） | **0.73–0.83** | ✅ 已修复（旧固件 ~2.5×），略偏低可后续微调 |
| v 执行增益 | ~1.2× | ⚠ 偏快 20%，次优先级 |
| **cmd→整车响应纯滞后** | **600–900 ms** | ❌ 当前主要矛盾 |
| 其中：ROS 软件链（DWB→smoother→david_move→串口） | 仅 60 ms | 软件链清白 |
| ⇒ 串口以下（固件环+机械） | **~0.6–0.8 s** | **全部延迟都在固件/整车侧** |
| 轮速计自报增益（odom vs cmd） | 1.03–1.05 | 自报与真值 v 差 ~15%，odom 标定一并核 |

后果：nav2 的 DWB 前向仿真假设零延迟。0.75s 滞后在实测振荡周期 7.6s 上
= 35° 相位损失，是当前直线蛇形（横向峰值实测 34–55cm）的主导根因。

## 2. 验收指标（每轮改完都按此复测，全部达标才算完）

在**满载（整机 70kg）、正常地面**条件下：

1. **wz 阶跃**（0 → 0.3 rad/s，滚动中叠加，即 vx=0.15 时）：
   90% 响应时间 **≤ 200 ms**，超调 ≤ 15%，稳态增益 0.95–1.05；
2. **v 阶跃**（0 → 0.15 m/s）：90% ≤ 300 ms（70kg 惯量+力矩限制，放宽），
   稳态增益 0.95–1.05；
3. 低速可持续：v = 0.05 m/s、滚动中 wz = ±0.10 rad/s 能稳定跟踪不抖振
   （上层软件死区抬升已全部撤除，固件必须自己吃掉静摩擦）；
4. 左右轮同指令阶跃，两轮编码器稳态转速差 **< 3%**；
5. 零指令静止时无自激抖动。

## 3. 测量手段

- **固件内部**（隔离固件环 vs 整车机械）：控制循环里以 ≥100Hz 打印/上传
  `t, 左轮目标, 左轮实测, 右轮目标, 右轮实测, PWM占空比/电流`。
  没有这一层日志就是盲调——先加它。
- **整车外部真值**：`alias 9`（`scripts/calibrate_plant_gains.sh`）自动做
  v/wz 阶跃并输出各档增益+纯滞后+死区标记（lightning 激光里程计做真值）。
  每轮固件改动后跑一次 `9 --tests wzroll,v --repeats 3` 即可。
- 串口指令回看：wheeltec `chassis.log` 里有每条 50Hz 下发（vx/wz 到 mm/mrad）。

## 4. 排查与调参步骤（按嫌疑优先级，一次只动一处）

### Step 0 —— 确认 cmd_vel 不经过位置环（头号嫌疑）

0.6–0.9s 的滞后量级 + "位置环速度环一起调过"这个背景，最大嫌疑是
**速度指令被裹进了位置环**（速度→积分成位置目标→位置环→速度环）。
位置环本质是一个积分器，在所有频率上引入 90° 相位滞后，表现恰好就是
"响应又慢又不超调"（过阻尼假象）。

检查：cmd_vel 收到后是否直接换算成**轮速目标**进速度环。
- 是 → 排除，进 Step 1；
- 否 → 改为直通速度环，位置环只服务于位置指令模式。**大概率此一步就修完。**

### Step 1 —— 指令斜坡 / 滤波器（二号嫌疑）

- 固件里若有加减速斜坡（slew limiter）：量出它的斜率。上游 ROS 侧已有
  加速度限幅（2.5 m/s² / 5 rad/s²），固件斜坡只该做安全兜底，
  **设为上游限幅的 ≥2 倍**，不许更紧。0.3 rad/s 阶跃若走 0.5 rad/s² 的
  斜坡就是 600ms —— 正好对上实测滞后，重点排查。
- 编码器测速滤波：滑动平均/一阶滤波时间常数 **≤ 50 ms**。200ms 级的滤波
  会直接锁死环路带宽。测速分辨率不够就提高采样窗内计数（M/T 法），
  别用加长滤波凑。

### Step 2 —— 速度环本体（每轮独立调，先空载后满载）

1. 空载（架起）：轮速目标阶跃，Kp 逐步加大到轻微超调（~10%）再回一档；
2. 加 Ki 消稳态误差，**必须带抗积分饱和**（力矩/PWM 饱和时停积分），
   否则大阶跃后会甩尾振荡；
3. 满载放地：重复。负载下大阶跃会进力矩饱和（响应变慢是物理极限，正常），
   验收看的是**巡航点附近的小信号**（0.15 m/s ±20%）——那才是 DWB 的工况；
4. 空载调好满载不行 → 先查电流限幅是否过低，再考虑增益调度。

目标带宽参考：轮速环闭环上升时间空载 <50ms、满载小信号 <100ms，
整车 wz 90% ≤200ms 自然达成。

### Step 3 —— 左右轮一致性（顺带终结"双轮不平衡"之争）

同目标同时阶跃左右轮，对比两轮编码器曲线：
- 稳态差 <3% → 电机/驱动一致性合格，剩余直线偏差交给上层闭环；
- 明显不一致 → 分轮标定增益（每轮独立的 speed→PWM 系数），
  别用统一系数硬凑。
（外部真值旁证：多晚的指令净偏置只占纠偏活动量 1–10% 且正负不定，
恒定性不平衡即使有也是小量，不要为它牺牲带宽。）

### Step 4 —— 低速死区

软件侧抬升（0.15 m/s 地板等）已全部撤除，固件要自己处理静摩擦：
- 首选 Ki 自然爬升克服（响应稍慢但平顺）；
- 嫌慢再加**方向性摩擦前馈**：按目标速度符号加固定小力矩偏置
  （从堵转临界 PWM 实测，取 ~80%）；
- 禁止用加大 Kp 硬怼摩擦——那是拿稳定裕度换死区，正是振荡来源。

### Step 5 —— 整车验收

`9 --tests v,wzstat,wzroll --repeats 3`：全部档位
增益 0.95–1.05、wz 滚动延迟 ≤0.2s、无 NO-RESP 死区标记 → 通过。
然后 nav2 直线实跑（headless），看 `/cmd_vel` wz RMS：目标从当前
0.32–0.40 降到 **<0.10**、饱和占比 0%。

## 5. 常见坑

- **一定满载调**：70kg 上身是被控对象的一部分，空载参数上车必然偏摆；
- **记录电池电压**：PWM→转速增益随电压漂，每轮记录，低电重测；
- 大阶跃看到"变慢"先查电流限幅再怀疑参数；持续跑发热后复测一轮
  （热漂移表现为增益缓降，不是振荡）；
- 每轮只动一个参数，改完立刻记录（见 §6），别攒一堆一起试。
